# تصريح دخول – المنطقة المحظورة | تحديث أكتوبر 2026

## تعليمات التحديث على الموقع الحالي

1. **احفظ نسخة احتياطية من قاعدة البيانات أولًا**. لا تشغّل schema.sql القديم مرة أخرى.
2. افتح مشروع Supabase الحالي > SQL Editor > New query، والصق محتوى `migration_v2.sql` ثم Run. التحديث لا يحذف التسجيلات القديمة.
3. ارفع ملفات `index.html` و`app.js` و`assets/theme-reference.jpg` المرفقة إلى جذر مستودع GitHub `Zone-64`، واستبدل النسخ القديمة.
4. **مهم: لا تستبدل config.js المنشور** بالنسخة النموذجية الموجودة في ZIP؛ احتفظ بملف config.js الحالي على GitHub وبالمفتاح العام الذي ضبطته سابقًا. لا تنشر كلمة مرور أو مفتاح sb_secret_.
5. تأكد من تحديث GitHub Pages ثم اختبر تسجيل عائلة وهمية من نافذة خاصة، وتحقق من ظهور اسمها فقط في قائمة العوائل، وجرّب تسجيل الدخول الإداري، إنشاء روم، توزيعه، نشره، واعتماد نتيجته.

## السلوك
- التسجيل بلا موعد: اسم العائلة وآيديها واسم المنسق وآيدي المنسق.
- العوائل المسجلة عامة بالأسماء فقط؛ البيانات الأخرى خاصة بالإدارة.
- الإدارة تنشئ عدد الرومات الذي تريده لكل يوم ثلاثاء أو أربعاء، وتحدد الوقت، وتوزع 8 عوائل كحد أقصى لكل روم.
- الجداول مخفية حتى يضغط المسؤول «نشر».
- الفائز والوصيف يتأهلان تلقائيًا بعد اعتماد النتيجة، بحد 32 لكل مسار.
- يسمح بثلاث مشاركات لكل عائلة (الأولى وفرصتان إضافيتان) قبل التأهل، وتمنع قاعدة البيانات التأهل المكرر.
- فتح وإغلاق التسجيل من لوحة الإدارة.

## ملاحظات
- **التوزيع عشوائي عند ضغط المسؤول زر القرعة**؛ ثم يراجع المسؤول الجدول وينشره.
- تاريخ البطولة الرئيسية: 2026-12-05. التواريخ الأسبوعية لا تُنشأ تلقائيًا؛ ينشئها المسؤول ويحدد عدد الرومات.
- عدد 32 رومًا × 8 عوائل = 256 مشاركة مطلوبة للوصول إلى 64 متأهلًا؛ العدد الفعلي من العوائل المسجلة يعتمد على تكرار المشاركة بحد ثلاث مرات.
- حساب المقاعد العامة مبني على النتائج المنشورة، بينما الإدارة ترى عدد النتائج المحفوظة؛ لإظهار التأهل للجميع انشر الروم.
- يتطلب اتصالًا بالإنترنت وتهيئة Supabase الصحيحة. لا تضع بيانات سرية في GitHub.

## الجدول المعتمد (تعديل 17 أكتوبر)
- من الثلاثاء 20 أكتوبر حتى الأربعاء 25 نوفمبر 2026: رومين كل ثلاثاء ورومين كل أربعاء (24 رومًا).
- روم تعويضي إضافي واحد في يوم ثلاثاء أو أربعاء سابق يحدده المسؤول (1 روم).
- الثلاثاء 1 ديسمبر 2026: 4 رومات.
- الأربعاء 2 ديسمبر 2026: 3 رومات، وليس 4.
- المجموع: 24 + 1 + 4 + 3 = 32 رومًا؛ 32 فائزًا و32 وصيفًا = 64 مقعدًا.
- هذه خطة مرجعية معروضة في الموقع؛ **لا تُنشأ الرومات تلقائيًا**. ينشئها المسؤول ويحدد توقيتها وينشرها من لوحة الإدارة، ويمكنه زيادة أو تقليل العدد.

## تثبيت القرعة العشوائية
شغّل `migration_v2.sql` ثم `migration_random_draw.sql` بالترتيب في SQL Editor بعد أخذ نسخة احتياطية. بعدها ارفع ملفات الواجهة إلى GitHub. لا ترفع `config.js` النموذجي فوق إعدادات الاتصال الحالية. القرعة تختار الأقل مشاركة أولًا، ثم عشوائيًا بين المتساوين.
